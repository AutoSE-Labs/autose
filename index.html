How it works

Every request takes the route it needs.

AutoSE sizes up each request first, so a quick question stays quick and real work gets a plan and an independent check. When a check fails, the work goes back for another pass before it ever reaches you. The dashboard draws every run this way, with the time each step took.

  1. Start Classify

    Auto reads the request and picks a tier: Spark for a question or a small edit, Craft for anything that needs a plan. You can pick one yourself instead.

  2. Forge Design Pro

    With Forge, a bigger change is decided against your ADRs and standards first, and the decision is written down as a new ADR.

  3. Step 1 Plan

    An ordered plan with numbered checks that every later step is held to. Read it before any work starts, if you like.

  4. Step 2 Execute

    The plan is carried out in your project. Every command waits for your answer, unless you have allowed it.

  5. Step 3 Validate

    A separate step that cannot write files checks each requirement, with evidence. If one fails, the work goes back to Execute.

    sent back until every check holds

  6. Then you Your review

    See the diff of every file it changed, then keep it or undo the run.

Tiers

The right amount of effort for every request.

Not every change needs a plan, let alone an architecture review. Auto picks a tier for each request, or you choose one yourself. Every session shows its tier as an icon, so you can tell them apart at a glance.

Spark

Answer, or one small edit

A question about your code, or a change small enough for one direct pass: a line, a value, a comment. No plan, just the answer or the edit.

Craft

Plan → Execute → Validate

Everything that needs a plan, from a bug fix to a change across many files. Planned, done and checked before you see it.

Forge Pro

Design, then as Craft

Architecture-level work gets a Design step first: decided against your ADRs and standards, and recorded as a new ADR before it is planned and checked.

Forge is part of AutoSE Pro. In the free edition, bigger changes run as Craft.

Features

Engineering you can account for.

Everything happens in a dashboard in your browser, in a light theme or a Catppuccin Mocha dark one, or in the terminal if you prefer. You decide what runs, and you can see what changed.

Local

Runs on what you own

AutoSE finds Ollama, LM Studio, vLLM or llama.cpp on your machine by itself. By default nothing leaves it: no third-party service, no telemetry.

Models

Made for small local models

It plans for the context window your runtime really serves, and tells you when that is smaller than the model allows. Small models sized to the task use far less energy than a giant cloud model.

Sessions

Several sessions at once

Run a long change in one session and ask a question in another. Rename them as you like; each shows its tier, and they pick up again after you close the window.

Route

See every step

Each run is shown as a route: every step with its timing, and every send-back marked where it happened and why.

Checks

Numbered checks

Requirements are numbered when the plan is written. You see each one go from written to done to verified, with the evidence for it.

Needs you

One list of what waits for you

Needs you gathers every question and plan waiting for an answer, from every session, so nothing sits unseen in a tab you are not looking at.

Questions

Asks before it runs anything

Commands wait in place with Run it, Always allow or Don't run, or tell it what to do instead. Always allow covers that kind of command, not your whole shell, and a chain of commands is judged part by part.

Allowed

See what runs without asking

The Allowed page lists every command that no longer asks first, so you can read it, change it or take it back.

YOLO mode

Nothing asks, when you mean it

One switch lets everything run without asking. A red frame stays round the window for as long as it is on, so you never forget.

Changes

Diff, undo and files

Read the diff of every change, undo a run, and browse the whole project in a read-only Files view.

Schedules

Schedules and watchers

Run a request on a schedule, or have a watcher run a command and start a request when its output changes or it starts failing.

Plan review

Read the plan first

Turn on Review the plan and the work stops once the plan is written. Approve and start, edit the plan, or stop there.

Benchmark

42 fresh tasks, small models, one GPU.

We ran the free edition of AutoSE, mini-swe-agent and OpenHands on SWE-rebench's June 2026 window: 42 real issues from 31 repositories, opened between 1 and 30 June 2026. Every agent got the same models, the same instruction and the same three hours per task.

mini-swe-agent 2.4.6 1 2.4% 5 11.9% 6/84 7.1% 49 / 30 min
OpenHands Agent SDK 1 2.4% 2 4.8% 3/84 3.6% 13 / 33 min
  • Tasks. SWE-rebench's 1 June to 1 July 2026 window: Rust 13, Python 9, Java 8, TypeScript 7, Go 5. Environments and graders come from SWE-rebench's own Harbor dataset; a task counts only when every fail-to-pass test passes.
  • Models. Gemma 4 12B-it (Google's QAT Q4_0 GGUF) and Qwen3.5-9B (Q4_K_M), served by llama.cpp on a single RTX 6000 Ada shared by both, 128K context per request, thinking off.
  • Harness. All three agents run through Harbor with their own default settings, the same SWE-rebench-style developer instruction, no step limit and a 3-hour limit per task. OpenHands uses its default context condenser.
  • One run per task. SWE-rebench's leaderboard averages five; with one run, a difference of one or two tasks is within noise. Trials interrupted by an inference-server outage were rerun.

Get started

One line to your first session.

The installer works the same way on macOS, Linux and Windows. Run it again any time to update.

  1. 1
    Install AutoSE
    Run the one-line command for your system. It downloads AutoSE, sets up Python with uv, adds an AutoSE shortcut to your desktop and opens the dashboard.
  2. 2
    Set up a local model
    AutoSE runs on a model you host. Install Ollama and pull a coding model that can call tools: ollama pull qwen2.5-coder:14b. AutoSE finds it by itself.
  3. 3
    Open it on your project
    Double-click the AutoSE shortcut and choose your project folder; the dashboard opens in your browser. In a terminal, autose --web does the same for the current folder, autose starts a terminal session and autose --doctor checks your setup.
macOS / Linux 
$ curl -fsSL https://autose.dev/install.sh | sh
Windows (PowerShell) 
> irm https://autose.dev/install.ps1 | iex

Want to read it first? Both scripts are plain text: install.sh and install.ps1. You can also build from source by following the README.
